# `/career` 求职页 · 自己编辑指南

> 面向：只想改几行字的人 → 看 **一**；想加一节/一张卡的人 → 看 **四**；改完想上线 → 看 **六**。
> 全文命令都在仓库根执行：`cd ~/Developer/wshazad.github.io`

## 0. 一分钟架构

```
career/content.json      ← 唯一内容源（77 条 key，每条 { "en": "…", "zh": "…" }）
career/index.html        ← 生成物（结构 + 英文内容），别手改文字
career/js/zh-i18n.js     ← 生成物（中文词典），完全别改
career/tools/template.html ← 生成物（结构骨架，文字处留哨兵）
career/css/style.css     ← 样式（与研究主页那份是两个独立文件）
career/js/app.js         ← 交互（中英切换、主题、滚动显现、点标题折叠、邮箱复制）
                             语言默认永远是英文（2026-09-05 改）：
                             · ?lang=zh 强制中文；站内切过「中文」只在本标签页保留（sessionStorage）
                             · 不再读 localStorage.lang，进页还会清掉残留 —— 误点一次中文不会永久改掉首页
tools/build.mjs          ← seed / build 两个命令
tools/studio.mjs         ← 本地编辑台（所见即所得 + 发布）
tools/sync-research.mjs  ← 与研究主页文案对齐
```

铁律：**只动字，不结构 → `build`；动了标签结构或新增文案位 → 先 `seed`、补中文、再 `build`。**

```bash
PI_SITE=career node tools/build.mjs build        # 用 content.json 重生成 index.html + zh-i18n.js
PI_SITE=career node tools/build.mjs seed         # 反过来：用 index.html 重生成 content.json + template
```

⚠️ `seed` 会**覆盖** `career/content.json`（英文取自 index.html，中文取自 zh-i18n.js）。日常不要顺手 seed。

## 一、改文字（最常用，不碰代码）

```bash
PI_SITE=career node tools/studio.mjs --port 3838      # → 浏览器打开 http://127.0.0.1:3838
```

> 不想开终端：**双击桌面上的 `求职页编辑台.command`**（端口 3838）；改研究主页就双击 `研究页编辑台.command`（端口 3839，两个可同时开）。
> 这两个启动器放在桌面、不在仓库里，所以不会被发布；里面只写了 `cd 仓库 + 起 studio`，路径变了改文件开头 `REPO=` 那一行。

右下角 **✎ 编辑本页** → 页面里任何文字直接点着改（黄色虚线框 = 可编辑）→ **💾 保存**（写 content.json + 重建 + 自动刷新）→ **🚀 发布上线**。

| 要点 | 说明 |
| --- | --- |
| 一次只存一种语言 | 面板上写着「作用于 中文 / English」。中英都要改 → 切语言、各改各存一次 |
| 撤销 | 回到本次进入编辑模式时的样子（**未保存前**有效） |
| 换图片 | 编辑模式下**直接点图片**选文件即可（自动同名覆盖 + `?v=` 破缓存） |
| 🚀 的范围 | 它跑的是 `git add -A`，作用在**整个仓库**：会把研究主页的未提交改动一起打包。只想发求职页 → 用 **六** 的手动命令 |
| 改坏了 | 没提交：`git checkout -- career`；已提交：`git revert HEAD` |

不想开编辑台，就直接改 `career/content.json`，然后 `PI_SITE=career node tools/build.mjs build`。

**值里能写什么**

- 可以：`<b> <strong> <em> <i> <small> <br> <a href="…"> <span class="lab">`；块级 key（如 `p1_flow`、`p2_bars`、`icm_body`）里可放 `<div class="flow-box">`、`<div class="bar"><span style="width:96%">`、`<li>`
- 不要：改 `class` 名、写 `<script>`、贴编辑器自动带出的内联 `style`（`style="background-color: rgba(245,158,11,…)"` 这类是脏东西；在编辑台里改颜色就会长出来，改完记得清）
- 中文里要空格用 `&nbsp;&nbsp;`，破折号统一用 `——`，倍数用 `×`
- `.lab` 只包**标签词**，值写在它外面：`<span class="lab">Data</span> 226 cities, 2003–2022`。
  写成 `<span class="lab">Data&nbsp;&nbsp;226 cities…</span>` 会让整句被塞进灰色小标签里（0.72rem 粗体 + 底框）。两个站已于 2026-09-04 统一成前者

## 四、改结构：加一张卡、加一节、换布局

只改 `career/index.html`，然后走一遍 seed：

```bash
PI_SITE=career node tools/build.mjs seed          # ① 以 index.html 为准重建 content.json
# ② 打开 career/content.json：新出现的 key 的 "zh" 是空字符串 → 补中文（空着不会报错，切中文时退回显示英文）
PI_SITE=career node tools/build.mjs build         # ③ 重生成页面
```

每个新文案位都要一个**全站唯一**的 `data-i18n="key"`，否则中英切换会串。没打 key 的内容不会被翻译，永远显示英文。

### 新增一整节（例：荣誉 Honors）

```html
  <!-- ============ Honors ============ -->
  <section id="honors">
    <h2 class="sec-title" data-reveal data-i18n="sec_hon">Honors</h2>
    <div class="item card" data-reveal>
      <ul data-i18n="hon_l"><li>…</li><li>…</li></ul>
    </div>
  </section>
```

再在导航里加一行（`id` 与 `data-nav` 必须同名）：

```html
      <a href="#honors" data-nav="honors" data-i18n="nav_honors">Honors</a>
```

顶部进度条、滚动高亮、移动端菜单都是 `js/app.js` 自动收集 `<section id>` 的，**不用改 JS**。
编辑台左侧的分组在 `tools/studio.mjs` 的 `GROUP_CAREER` 里（正则/前缀匹配）——新增一批同前缀的 key 时顺手补一行，不然会掉进「其他」。

## 五、样式、主题、断点

- `career/css/style.css` 顶部是变量：`--accent`（主色）、`--rr-bg/--wp-bg/--aw-bg`（三种徽章底色）、`--surface-2`、`--rule`；`[data-theme="dark"]` 覆盖一整套 → 用变量写样式，深色模式自动就好。
- 求职页专有网格：`.strengths`、`.skill-grid`（三列自适应，≤720px 单列）。
- 导航 6 项，**880px 起收起成汉堡**（约 191 行）；研究主页 5 项用的是 720px，两份互不影响。
- 整页最大宽度 = `var(--wrap-max)`，默认 880px（`.wrap` / `.nav-inner`）；断点仍是写死的 `@media (max-width: 880px)`，**不跟着 `--wrap-max` 动**：把版心拉到 1040/1080 也不会提前收汉堡，只是内容变宽（窄屏不会横向溢出，因为 `max-width` 永远不会宽过窗口）。

### 版式旋钮：字号 / 字体（不用改代码）

单一来源 **`career/theme.json`** → 生成 **`career/css/theme.css`**（`index.html` 在 `style.css` 之后加载它，只覆盖变量）。
所有尺寸都是 `rem`，所以 `--fs-root` 一动全站等比缩放；`style.css` 的 `:root` 里每个变量都有默认值，**theme.css 偶尔加载不到也不会把页面搞坏**（不会退化成浏览器默认字体）。

8 个旋钮（`theme.json` 字段名）：

| 旋钮 | 字段 | 区间 | 默认 | 作什么 |
| --- | --- | --- | --- | --- |
| 全局字号 | `fs_root_pct` | 88–128% | 100 | 1rem 基准 = 全站文字（导航、正文、图注）一起大/小 |
| 主标题 | `scale_h1` | 0.8–1.4× | 1 | hero 的 `h1`（连带中文名 `.cn`）单独再放大 |
| 小节标题 | `scale_h2` | 0.8–1.4× | 1 | `.sec-title`（研究/教育/技能…）单独放大 |
| 主标题行距 | `lh_h1` | 1.0–1.7 | 1.15 | 标题放大后防撑高的旋钮；想要旧版那种宽松感调回 1.55 |
| 正文行距 | `lh_body` | 1.35–1.95 | 1.55 | 正文疏密 |
| 版心宽度 | `wrap_max_px` | 720–1080 | 880 | 一行多少字 |
| 正文字体 | `font_body` | 预设 key | `sans` | 系统无衬线 / 人文 / Helvetica / UI / 等宽 / 两种衬线 |
| 标题字体 | `font_display` | 预设 key | `georgia` | 作用于 `h1` `.sec-title` `.brand` `.stat .num` `.chan-box span` |

字体预设表在 `tools/theme.mjs` 的 `FONT_PRESETS`，**只用系统字体**（不发外部字体请求：隐私、离线、首屏快）；想要 Inter/Source Serif 这类真字体，在 `FONT_PRESETS` 加一条 stack 并在 `index.html` 加 `<link>`（要进 `tools/template.html`，否则下次 build 会被洗掉）。

两条改版式的路：

1. **编辑台（所见即所得）**：`PI_SITE=career node tools/studio.mjs --port 3838` → 右下角**「Aa 版式」**（在「✎ 编辑本页」上面一行）→ 拉滑块即时预览 → 💾 保存版式（写 theme.json + 重生 css）→ 🚀 发布上线。面板右下角不遮 ✎ / Aa 两个按钮；窗口很矮时面板自身滚动。`Esc` 或 ✕ 关闭会刷新预览（未保存的调整丢弃）。
2. **在 GitHub 网页上改**：直接编辑 `career/theme.json`（数字可以是 `112`、`"112"`，两者都吃）→ push → Actions 自动重生 theme.css。**不要手改 `career/css/theme.css`**，它是生成物，下一次 build 会被覆盖。

非法值不会弄挂站点：`clampTheme()` 把数字夹到上表区间，坏值/缺字段/多余字段/整个文件不是合法 JSON → 退回默认并打一行 `⚠ theme.json 不是合法 JSON` 警告（在 Actions 日志里能看到）。新加旋钮后 `theme.json` 会在首次 build 时自动补齐该字段默认值，所以在网页上永远看得到全部 8 个。

## 七、与研究主页同步（`tools/sync-research.mjs`）

两个站有 **45 个同名 key**（论文标题、问题句、图注、机制块、关键结果、教育/经历字段）。研究页改了，求职页**不会自动跟**，反之也一样。

```bash
node tools/sync-research.mjs --dry-run          # 先看会改什么（强烈建议每次都带）
node tools/sync-research.mjs                    # 默认范围：p1_ p2_ p3_ icm_
node tools/sync-research.mjs edu_ sec_ b_jrs    # 位置参数 = 前缀白名单
node tools/sync-research.mjs --all              # 全部同名 key（自动跳过 footer / hero_role / hero_int）
node tools/sync-research.mjs --from career      # 求职页 → 研究主页（反向同步就这条；两边都改过时也是裁决）
node tools/sync-research.mjs --include-style-only --from main   # 连 HTML 标记一起对齐（默认不动样式）
```

它怎么保证不互相覆盖：

1. 每次同步把结果记进基线 `tools/.sync-research.state.json`；
2. 某条 key **只有一边**相对基线变过 → 从那边搬到另一边；
3. **两边都改且不同** → 判为冲突：列出来、不动手、退出码 2，等你用 `--from` 裁决；
4. 文字一模一样、只是内联样式/标记不同 → 默认视为相同、不动，只提示；要把格式也拉平就加 `--include-style-only`（当初就是用它把 `.lab` 的正确写法从研究主页推到求职页的）；
5. `footer` / `hero_role` / `hero_int` 两个站**故意**写得不同（学术口吻 vs 求职口吻），除非 `--force` 永不参与；
6. 单边独有的 key（求职页 `sk1…`，研究主页 `p1_abs`、`phd`…）只提示，永不复制；
7. 图片路径自动改写：研究主页 `assets/…` ↔ 求职页 `../assets/…`；
8. 不管从哪边写，落笔前都会先 `defunk`：把编辑台塑进 `.lab` 的那层内联样式（`<span class="lab">Data：<span style="background-color: rgba(245,158,11,…)">值</span></span>`）拉平成 `<span class="lab">Data：</span> 值`，所以这种垃圾不会被带到另一个站（但本站页面上还是会有，发现标签变成一大块灰底就手动清一下）。

同步完它会自动重建被改那一站的 `index.html` + `zh-i18n.js`（`--no-build` 可关掉）。
基线文件建议别进版本库：仓库根的 `.gitignore` 里加了 `tools/.sync-research.state.json`。

## 十一、在 GitHub 网页上直接改 → 自动上线（Actions 部署）

部署链路已改成 **GitHub Actions 构建**：`.github/workflows/deploy.yml` + `tools/pack-site.sh`。
每次 push 到 `main`（包括在 github.com 上点铅笔编辑、直接 Commit）都会：
`node tools/build.mjs build`（研究主页）→ `PI_SITE=career node tools/build.mjs build`（求职页）→ `pack-site.sh` 打包成 `_site` → 上传 artifact → Pages 部署。
所以**不用本地 build、不用本地 push 命令**，网页上提交即上线。

### 该改哪个文件（改错文件=白改）

| 想改什么 | 在 GitHub 上打开这个文件 | 说明 |
| --- | --- | --- |
| 文字、标题、日期、链接文案 | `career/content.json` / 根 `content.json` | 双语 `{en, zh}`，key 见 **三** |
| 字号、字体、行距、版心宽度 | `career/theme.json` / 根 `theme.json` | 8 个旋钮，**不用碰 css**；含义见 **五·版式旋钮**，本地也能用编辑台「Aa 版式」拖滑块 |
| 颜色、主题、间距、卡片布局 | `career/css/style.css` / 根 `css/style.css` | `:root` 里的 `--accent/--surface-2/--rule` 等配色变量在这里；51 / 46 处 `font-size` 已是 `rem`，跟着 `--fs-root` 走 |
| 版式、加删一节、标签结构 | `career/tools/template.html` / 根 `tools/template.html` | 只改文字的话不要碰这里 |
| 照片、研究配图、非简历 PDF | `assets/` `career/assets/` | 直接拖文件上传覆盖 |
| ~~`index.html`~~ | ❌ 别改 | 构建生成物，下一次 push 就被覆盖回去 |

改 `content.json` 里新增/删除 key 时记得两边对齐（研究主页与求职页有 45 个同名 key，见 **七**）。
只在 `content.json` 出现、模板里没有对应 `data-i18n` 哨兵的 key，build 会打 `模板缺哨兵` 但**不报错**（当前有 `nav_research`、`p1_chanvs` 两条历史遗留），那条文字就不会出现在页面上 → 要它显示就去 `template.html` 加元素。

### 一次改动的操作

1. github.com 上打开文件 → 铅笔图标编辑 → **Commit directly to `main`**（一次一个文件、写清 commit message）。
2. `Actions` 页面看 `Deploy site` 跑绿（约 1–2 分钟）。
3. 打开线上地址确认；HTML 缓存最多 10 分钟，看不到新版就硬刷新或地址后加 `?t=1`。

`pack-site.sh` 只发布站点文件，以下**从线上消失**（仓库里照样能看）：

### 一次性开关（不做这一步，workflow 的 deploy 步骤会红）

`Settings → Pages → Build and deployment → Source` 改成 **GitHub Actions**。
改之前站点仍按旧方式（分支根目录）发布，不会中断；改完之后手动跑一次 `Actions → Deploy site → Run workflow` 让两边对齐。

### ⚠️ 改完别急着信「格式化顺手」

`tools/template.html` / `career/tools/template.html` 是**紧凑写法**的构建源。编辑器/工具链若把它整体重排（prettier 把属性拆行），`build` 出来的 `index.html` 会多出几百行纯换行——肉眼看不出问题，但 review 和回滚都会被淹掉。判断方法：改完跑一次两站 build，`git status --porcelain` 里出现 `index.html` 且 `git diff --stat` 是几百行量级，就是被重排了，`git checkout -- .` 回滚重来。
